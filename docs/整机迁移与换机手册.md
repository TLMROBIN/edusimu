# 整机迁移与换机手册

这份文档用于以下场景：

- 把当前系统迁移到另一台电脑
- 从旧服务器换到新服务器
- 保留现有数据、课件、配置与访问方式

这份文档默认目标是：

- 在新机器上恢复出一个和当前系统功能一致的可运行环境
- 尽量降低“迁过去能启动，但课件丢了或访问不正常”的风险

---

## 1. 当前线上实际情况

当前线上部署不是纯开发环境，而是正式运行形态。

关键事实：

- 线上后端目录：`/var/www/edusimu/backend`
- 线上前端目录：`/var/www/edusimu/frontend/dist`
- 线上 Nginx 监听端口：`3003`
- 线上后端内部端口：`8000`
- 线上数据库：`PostgreSQL`
- 线上数据库连接串在：
  - `/var/www/edusimu/backend/.env`

当前线上 `.env` 里的关键项：

- `DATABASE_URL=postgresql://edusimu:edusimu123@localhost:5432/edusimu`
- `UPLOAD_DIR=./uploads`

这意味着迁移时不能只带源码，至少还要带：

- PostgreSQL 数据库
- `uploads/`
- `.env`
- Nginx 配置
- systemd 服务配置

---

## 2. 不建议的迁移方式

不建议直接整盘克隆旧机器系统盘到新机器，原因包括：

- 新机器硬件和驱动不同
- EFI/启动配置可能不同
- 磁盘 UUID 变化
- 网络和挂载点变化
- 整机克隆后排障成本更高

推荐方式是：

- 新机器重装系统
- 重新部署程序环境
- 恢复数据库、上传文件和配置

这叫“应用级迁移”，通常比整机克隆更稳。

### 3.2 线上配置

- `/var/www/edusimu/backend/.env`

## 4. 旧机器上建议先做的事情

在真正迁移前，建议先在旧机器上完成这些准备：

### 4.1 统一整理迁移包

建议创建一个迁移备份目录，例如：

```bash
mkdir -p /home/binyu/edusimu_migration_backup
```

### 4.2 导出数据库

示例：

```bash
pg_dump -U edusimu -h localhost -d edusimu > /home/binyu/edusimu_migration_backup/edusimu.sql
```

如果需要自定义格式：

```bash
pg_dump -U edusimu -h localhost -Fc -d edusimu -f /home/binyu/edusimu_migration_backup/edusimu.dump
```

### 4.3 打包上传文件

```bash
tar -czf /home/binyu/edusimu_migration_backup/uploads.tar.gz -C /var/www/edusimu/backend uploads
```

### 4.4 备份线上配置

```bash
cp /var/www/edusimu/backend/.env /home/binyu/edusimu_migration_backup/backend.env
cp /home/binyu/文档/trae_projects/edusimu/nginx/edusimu.conf /home/binyu/edusimu_migration_backup/edusimu.conf
cp /home/binyu/文档/trae_projects/edusimu/nginx/edusimu-backend.service /home/binyu/edusimu_migration_backup/edusimu-backend.service
```

### 4.5 备份源码

```bash
tar -czf /home/binyu/edusimu_migration_backup/source.tar.gz -C /home/binyu/文档/trae_projects edusimu
```

### 4.6 记录当前状态

建议额外保存：

```bash
systemctl status edusimu-backend --no-pager > /home/binyu/edusimu_migration_backup/backend.status.txt
systemctl status nginx --no-pager > /home/binyu/edusimu_migration_backup/nginx.status.txt
hostname -I > /home/binyu/edusimu_migration_backup/ip.txt
```

## 5. 新机器的目标环境

建议新机器环境：

- Ubuntu 20.04 / 22.04 / 24.04
- PostgreSQL
- Nginx
- Python 3
- Node.js

建议目录仍保持一致：

- `/var/www/edusimu/backend`
- `/var/www/edusimu/frontend/dist`

这样现有脚本和配置改动最小。

---

## 6. 新机器安装步骤

### 6.1 安装基础依赖

大致需要：

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip nginx postgresql postgresql-contrib nodejs npm
```

如果 Node 版本过旧，再单独装新版 Node。

### 6.2 创建目录

```bash
sudo mkdir -p /var/www/edusimu/backend
sudo mkdir -p /var/www/edusimu/frontend
```

### 6.3 恢复源码

把备份的源码解压到工作区，或直接从旧机器拷贝：

- `/home/binyu/文档/trae_projects/edusimu`

### 6.4 恢复线上后端代码

把后端代码放到：

- `/var/www/edusimu/backend`

通常可以直接复制 `backend/` 内容。

### 6.5 恢复 `.env`

把旧机器的：

- `backend.env`

恢复到：

- `/var/www/edusimu/backend/.env`

---

## 7. 数据库恢复

### 7.1 创建数据库和用户

如果新机器上还没有 `edusimu` 数据库：

```sql
CREATE USER edusimu WITH PASSWORD 'edusimu123';
CREATE DATABASE edusimu OWNER edusimu;
```

### 7.2 恢复 SQL

如果导出的是纯 SQL：

```bash
psql -U edusimu -h localhost -d edusimu < edusimu.sql
```

如果导出的是 `pg_dump -Fc`：

```bash
pg_restore -U edusimu -h localhost -d edusimu edusimu.dump
```

### 7.3 恢复完成后验证

至少确认：

- `users`
- `animations`
- `textbook_nodes`
- `view_histories`

这些表里有数据。

---

## 8. 上传文件恢复

把旧机器导出的：

- `uploads.tar.gz`

恢复到：

- `/var/www/edusimu/backend/`

示例：

```bash
cd /var/www/edusimu/backend
sudo tar -xzf /path/to/uploads.tar.gz
sudo chown -R www-data:www-data /var/www/edusimu/backend/uploads
```

注意：

- 这一步必须做
- 只恢复数据库不恢复 `uploads`，课件会显示存在但打不开

---

## 9. 后端恢复与启动

### 9.1 创建虚拟环境

```bash
cd /var/www/edusimu/backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### 9.2 编译检查

```bash
python -m compileall app
```

### 9.3 初始化补字段

可以直接运行项目现有逻辑：

```bash
python - <<'PY'
from app.database import SessionLocal
from app.init_db import init_database

db = SessionLocal()
try:
    init_database(db)
finally:
    db.close()
PY
```

## 10. 前端恢复与部署

### 10.1 构建

```bash
cd /home/binyu/文档/trae_projects/edusimu/frontend
npm install
npx vite build --outDir dist-local
```

### 10.2 部署

```bash
sudo rm -rf /var/www/edusimu/frontend/dist
sudo mkdir -p /var/www/edusimu/frontend/dist
sudo cp -r /home/binyu/文档/trae_projects/edusimu/frontend/dist-local/* /var/www/edusimu/frontend/dist/
sudo chown -R www-data:www-data /var/www/edusimu/frontend
```

## 11. Nginx 与 systemd 恢复

### 11.1 Nginx

把旧机器的 `edusimu.conf` 放到新机器 Nginx 配置位置，常见是：

- `/etc/nginx/sites-available/edusimu.conf`

再建立链接：

```bash
sudo ln -s /etc/nginx/sites-available/edusimu.conf /etc/nginx/sites-enabled/edusimu.conf
```

测试配置：

```bash
sudo nginx -t
```

### 11.2 systemd

把 `edusimu-backend.service` 放到：

- `/etc/systemd/system/edusimu-backend.service`

然后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable edusimu-backend
sudo systemctl restart edusimu-backend
sudo systemctl restart nginx
```

## 12. 新机器上线前的最小验收

至少要验证：

1. `edusimu-backend` 服务是 `active`
2. `nginx` 服务是 `active`
3. 访问首页能打开
4. 能正常登录
5. 首页课件列表可加载
6. 打开一个旧课件能正常播放
7. 上传课件能成功
8. 教材目录页面能正常打开
9. 后台统计页能正常返回数据

## 13. 推荐的迁移顺序

最推荐的顺序是：

1. 旧机器导出数据库
2. 旧机器打包 `uploads`
3. 旧机器备份 `.env` 和 Nginx/systemd 配置
4. 新机器安装依赖
5. 新机器恢复数据库
6. 新机器恢复 `uploads`
7. 新机器恢复后端
8. 新机器构建并部署前端
9. 新机器恢复 Nginx 和 systemd
10. 验证功能
11. 切换使用

---

## 14. 迁移失败时优先排查什么

### 14.1 页面能打开但课件打不开

优先检查：

- `/var/www/edusimu/backend/uploads` 是否恢复完整
- `.env` 中 `UPLOAD_DIR` 是否正确
- `/uploads/` 路径映射是否正常

### 14.2 能登录但数据不对

优先检查：

- PostgreSQL 是否恢复了正确数据库
- `.env` 中 `DATABASE_URL` 是否指向正确实例

### 14.3 前端一直是旧页面

优先检查：

- `/var/www/edusimu/frontend/dist` 是否真的被替换
- 是否重启了 `nginx`
- 浏览器是否缓存

### 14.4 后端启动失败

优先检查：

- `.env`
- Python 依赖是否安装齐
- PostgreSQL 是否可连接
- `journalctl -u edusimu-backend -n 100 --no-pager`

---

## 15. 最稳的做法

如果条件允许，建议迁移时保留旧机器一段时间，不要立刻销毁。

最稳策略是：

- 新机器完整恢复并通过验收
- 局域网先试运行
- 确认学生和教师能正常使用
- 再正式切换

这样即使新机器出现问题，也能快速回退到旧机器。
