## 二、关键参数解读与动画制作参考

| 维度 | 实测值 | 对后续动画制作的参考意义 |
| --- | --- | --- |
| **运行环境** | Android 11 (`M9 Build/RP1A.201005.001`) + Android WebView (`wv`) | 属于嵌入在客户端 WebView 中的运行环境，非桌面级独立浏览器。 |
| **浏览器内核** | Chrome `106.0.5249.126` | 支持 ES2020、`PointerEvent`、`ResizeObserver`、`localStorage`；**不可使用** Chrome 107+ 才支持的新特性（如 CSS Nesting、Popover API、`@starting-style`、ES2023+ 新语法等）。 |
| **视口与分辨率** | 屏幕 CSS：`1098 × 686`<br>窗口 CSS：`1016 × 563`<br>DPR：`1.75` | 物理分辨率约 `1920 × 1200`。内嵌播放区域有效 CSS 高度仅 **563 px**（宽 **1016 px**），横屏紧凑布局：动画画布与控制栏需保证在 `1016 × 563` 下**无垂直滚动条**、控件不被遮挡。 |
| **硬件与帧率** | 8 核 CPU、**4 GB 内存**，平均 **33.6 fps**，95% 帧时间 **48.2 ms**，卡顿帧（`>50 ms`）`0` | 该平板实际渲染帧率约 30~34 fps（非 60 fps 满帧），单帧耗时接近 30~48 ms，且可用内存仅 4 GB：<br>1. 物理/运动计算必须基于 **`dt`（时间增量）**，不能假设 60 fps 固定步长；<br>2. Canvas 绘制建议控制渲染压力（如适度限制 DPR 上限至 `1.5~1.75`、避免每帧大量阴影/模糊滤镜/全屏重绘静态背景），确保帧时间稳定在 `50 ms` 以内；<br>3. 注意内存控制：避免创建过多大尺寸离屏 Canvas、高清位图或未清理的粒子/历史轨迹数组，防止 WebView 内存吃紧导致页面被回收。 |
| **触控能力** | 最大触控点数：`2` | 仅支持双指及以下触控，交互手势应以**单指拖拽/点击**为主，最多用到双指缩放，不设计三指及以上手势；同时适配 `PointerEvent`。 |
