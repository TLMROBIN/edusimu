# 力学实验系列课件与开发计划审查

审查日期：2026-11-20。对象：`courseware/mech-lab-2027` 的 M00–M09、公共库、各模块 SPEC、SERIES 总规范，以及《作答收集与课堂弹幕互动实施计划》。

结论：发现 **8 项缺陷（2 项 P1、6 项 P2）和 1 项开发计划接入缺口**。建议修复 P1 并完成物理、排版问题整改后再进行全系列验收。现有自检全部通过，不能据此认定课堂交付通过。本轮未修改实现代码、未更新 public 发布文件、未部署；执行构建重新生成了 dist 文件，并保存本报告与审查证据。

## 1. [P1] 切换分区后实验动画无法继续

- 位置：`modules/M04-projectile/scene.js:1776`；同类实现见 M03:1861、M07:1271、M08:1707 附近的 `ML.bus.on('tab', ...)`。
- 原因：离开实验台只调用 `bench.loop.stop()`；返回时既没有恢复循环，也没有清除实验的 running/anim 状态。Shell 只会首次挂载实验台，返回不会重新创建它。
- 已在 M04 浏览器复现：点击“用小锤击打”，运行中切至“学·原理”再返回。`stA.running === true`，`loop.running === false`，击打按钮仍 disabled，双球停住，只能重置。M03/M07/M08 为同类代码风险，本轮未分别执行完整操作链复现。
- 建议：明确分区切换为“暂停并可恢复”或“中止并同步复位”；集中管理运行状态，避免 UI 与循环分离。验收覆盖飞行中、纸带运行中、连续碰撞中切换往返。

## 2. [P1] 作图判分允许明显偏离数据的平行线通过

- 位置：`core/paper.js:254–260`，尤其第 258 行。影响所有使用公共 Paper 的 plot 小问。
- 原因：仅检查参考点附近存在用户描点，以及直线斜率在容差内；未检查截距、点到线残差，也未拒绝多余坏点。
- 已调用真实浏览器的 `Paper.renderPart(...).grade()` 复现：M09 Y1(2) 正确描出 5 个参考点，用户直线设为 `(0,0.600)` 至 `(1,0.848)`，即 `L = 0.248T² + 0.600`。它明显远离数据（例如 T²=2 时直线 L=1.096 m，数据为 0.500 m），仍返回 `true`，显示“✓ 描点 ✓　斜率 0.248 ✓”。
- 建议：按坐标范围归一化检查残差或截距；需过原点的题另加原点条件；对点位匹配采用一一对应，限制额外点。验收应包含“正确斜率但错误截距”的反例。

## 3. [P2] M06 对称分力超量程的临界夹角算错

- 位置：`modules/M06-forces/scene.js:1018`。
- 数据分析图图例写“5.0 N 量程红线（α > 106° 即超程）”，同图标明等效合力 4.00 N。
- 正确关系：`F = 4 / [2 cos(α/2)]`。令 F=5，得到 `α = 2 arccos(0.4) ≈ 132.84°`。浏览器中调用课件实际模型得到：106° 时约 3.323 N；120° 时 4.000 N，均未超程。
- 这会使文字结论与课件自己的理论曲线、读数及推荐的 60°～120° 范围冲突。应从合力、量程实时计算临界角，替换硬编码 106°。

## 4. [P2] M08 气垫导轨动画和数值模型采用不同的碰撞位置

- 位置：`modules/M08-momentum/scene.js:255` 与 `:1008–1027`。
- 数值模型用 `xC - xStart = 0.60 - 0.18 = 0.42 m` 计算入射滑块碰撞前速度。
- 动画考虑了 0.095 m 的滑块长度：中心运行至 `0.60 - 0.095 = 0.505 m` 即发生碰撞，实际加速距离为 0.325 m，却直接切换成基于 0.42 m 算出的碰后速度。
- 对 UI 可选的导轨倾角 +1.35°、理想条件、初速度 0.8 m/s，模型碰撞速度约 0.66787 m/s；动画到接触位置时应为 0.69995 m/s，相差约 4.80%。水平无加速度时此差异被掩盖，未调平误差演示会暴露速度跳变。
- 建议：统一“滑块中心/前沿/接触点”的坐标定义，模型与动画使用同一几何参数及碰撞事件；同时检查碰后光电门路程。

## 5. [P2] M05 同直径材料球与严格质量比的叙述不自洽

- 位置：`modules/M05-centripetal/content.json:101`；模型 `scene.js:6`，图形预设 `scene.js:199–202`。
- 器材卡称几何直径相同的铝、钢、铜球分别为 20/40/60 g，质量比“严格为 1:2:3”。普通均匀实心材料球的质量比由密度决定，不能这样指定。例如铝与铜的常用密度约为 2.70、8.96 g/cm³，等体积铜铝质量比约 3.32，而非 3。数据参考：[英国皇家化学学会：铝](https://periodic-table.rsc.org/element/13/Aluminium)、[铜](https://periodic-table.rsc.org/element/29/copper)。
- 图形还使用不同的球半径 9、10、10.5，与“几何直径相同”不符。
- 建议：保留方便控制变量的 m/2m/3m 设计时，改称“等外径、经配重的小球 A/B/C”，颜色仅作区分；或采用真实材料与密度计算质量。让器材卡、模型和绘制半径统一。

## 6. [P2] 61 个原理页展开后全部需要长距离滚动

- 位置：`core/shell.js:81–103` 的逐步追加与底部导航；`core/base.css` 的 `.learn-card/.learn-steps/.learn-bar`。
- 与 `SERIES.md:27` 的“一页一个核心点、翻页、不做长滚动”不符。
- 在真实 iframe 的 1016×563 CSS 视口中逐页点击、展开全部步骤：10 个模块共 61 页均超过 `.ml-main` 可用高度 516 px。
- 例：M00 第 3 页内容高 990 px；M04 第 5 页 1273 px；M01 第 5 页 1647 px，约为可用高度 3.19 倍。下一步/下一页按钮位于内容底部，讲授时需要反复滚动找导航；并非隐藏内容丢失，但严重偏离分页授课目标。
- 建议：按推导过程增加子页，或仅保留当前及必要的前一步；把导航固定在可用区域。不要通过进一步缩小字号压入一屏。
- 截图：`mech-lab-2027-20261120/M01-learn-overflow.png`；逐页数据见 `learn-layout.json`。

## 7. [P2] M9 紧凑样式把大量实际触控热区缩到 26–32 px

- 位置示例：`modules/M06-forces/scene.css:96–115`；M09 同类规则 `scene.css:92` 之后；公共 `base.css:138–142`。
- 与 SERIES §4 “热区 ≥44 px”冲突。M06 侧栏 chip 最低高度 26 px、操作按钮 31 px；M09 参数 chip 28 px。浏览器统计各实验台初始状态都有 18–39 个可见按钮高度不足 40 px（不是仅有文字看起来小，而是按钮本身尺寸不足）。
- 原因说明文字亦常缩至 11.5–12 px；电脑可阅读，但投屏后排可读性尚不能通过此次桌面检查认定合格。
- 建议：保留至少 44 px 的实际点击面积，通过参数分组、按步骤展开、减少同时出现的控件来适配。真机检查相邻按钮误触与长按读数操作。

## 8. [P2] 7 个 public 课件没有包含当前公共库改动

- 位置：`frontend/public/mech-lab-2027/` 与当前源码构建的 `courseware/mech-lab-2027/dist/`。
- 执行 `python3 courseware/mech-lab-2027/build.py all` 后逐字节比较：M00、M01、M03、M04、M07、M08、M09 不一致；M02、M05、M06 一致。
- 已定位的差异包括提示条的顶部/底部位置、竖屏标题宽度、图例定位、交互图斜率显示精度。例如 public 旧版图中 `k.toFixed(2)` 的显示与当前源码的有效数字显示不同。使用 public 文件的交付路径会继续输出旧版行为。
- 这里证明的是本地发布副本陈旧，不代表已经查明线上部署版本。
- 建议：修复后一次构建发布全部模块，发布前核对哈希；把源码构建、public 同步、平台上传与线上验证分别记录。当前 `all` 不带 `--publish` 本来就不会更新 public，流程必须显式包含同步。

## 9. 开发计划缺口：力学系列尚未接入作答收集规范

- 计划依据：《作答收集与课堂弹幕互动实施计划》阶段 3、任务 1（约第 211 行）明确要求力学系列自动生成 `edusimu-quiz-manifest`，并由 ml/paper/shell 发送 `EDUSIMU_QUIZ_SUBMIT`。
- 当前 `build.py:157–163` 仅输出 ml-content、ml-questions 与运行脚本；四个约定文件中均没有上述 manifest/提交协议。公共 Paper 只向本地总线发送 `paper:graded`，且载荷仅题目 ID 与“是否全对”。10 个构建产物均未接入平台收数协议。
- 因此这套课件可以本地判分存档，但不能作为“平台已可收集逐小问作答、首答/最终结果及作答分布”的验收证据。
- 这是尚未落地的计划项，不能当作已完成能力；也不影响其作为独立离线课件加载。
- 接入时需新增稳定的逐小问 ID，并区分“用户提交”与“刷新后恢复已提交答案”。当前 `Paper.renderQ` 的 `if(saved.sub) grade()` 会自动重判，若直接在 grade 内无差别上报，会将刷新计为新作答。需专门设计恢复与上报边界。

## 对开发计划的修订建议

1. 将“已实现”“自动检查通过”“浏览器场景通过”“M9 真机通过”“已发布并核对版本”拆成独立状态，附版本哈希和证据路径。
2. M01 黄金样板验收增加“原理页全展开”“图线错误截距”“运行中切换分区”“刷新恢复不重复上报”四项，再扩展全系列。
3. 物理验证应覆盖 UI 展示的临界值和动画事件坐标，避免仅检查计算函数或将答案与自身比较。M06 临界角、M08 接触时刻应列为独立反例。
4. 作答协议接入与 public/平台发布分别设置准入检查，不把“dist 构建成功”作为全链路完成。
