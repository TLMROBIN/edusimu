# 系统接手与维护指南

这份文档面向两类读者：

- 新接手这个项目的开发者、运维或产品负责人
- 需要继续迭代这个系统的 AI 编程工具

目标不是介绍所有细节，而是让接手者在最短时间内理解：

- 这个系统是干什么的
- 当前已经做到什么程度
- 课件必须满足什么标准
- 日常改动应该从哪里入手
- 哪些设计约束不能轻易破坏

---

## 1. 系统定位

这是一个面向校内内网和平板终端的教学课件平台。

核心使用方式：

- 教师登录自己的账号上传 HTML 课件
- 上传时必须绑定教材章节
- 系统自动校验课件是否适合平板触控和内网离线使用
- 管理员审核并发布课件
- 学生在平板上按学科、教材章节或关键词查找课件并使用
- 平台统计学生使用数据，用于评估课件效果

这个系统不是通用 CMS，也不是在线网页托管平台。  
它的中心目标是：

- 让课件在校内平板上稳定运行
- 让课件和教材目录严格对应
- 让教师和管理员能看到课件使用效果

## 2. 当前业务模型

### 2.1 角色

- `student`：学生，浏览和使用已发布课件
- `teacher`：教师，上传和管理自己的课件
- `admin`：管理员，管理全站用户、教材目录、审核和发布课件

### 2.2 核心业务流程

1. 管理员先维护教材目录树
2. 教师登录后上传 HTML 课件
3. 上传时必须选择所属章节
4. 系统自动校验课件
5. 校验失败则提示问题和 AI 修复 Prompt
6. 教师上传修订版覆盖原记录
7. 管理员审核并发布
8. 学生按章节筛选并使用
9. 系统统计观看、交互、评分、收藏等数据

### 2.3 课件记录的重要字段

课件表 `animations` 的关键语义：

- `title`：课件标题
- `subject_id`：学科
- `textbook_node_id`：所属教材末级节点，必须有值
- `author`：展示作者名，默认自动用教师姓名/用户名
- `created_by`：实际上传账号
- `thumbnail`：缩略图地址，可为空
- `validation_status`：校验状态
- `review_status`：审核状态
- `is_published`：是否发布

这几个字段不要混淆：

- `author` 是展示信息，可编辑
- `created_by` 是权限归属，不能随便改语义
- `textbook_node_id` 是统计聚合的基础字段，不能放宽为可空

## 3. 当前功能范围

### 3.1 已实现

- 登录认证与角色权限
- 教师自助上传课件
- 上传自动署名
- 强制绑定教材章节
- 教材目录管理
- 按章节筛选课件
- 课件审核与发布
- 修订版覆盖上传
- AI 修复建议
- 章节维度统计
- 教师个人效果视图
- 用户 Excel 导入
- 平板沉浸播放模式

### 3.2 已实现但有边界

- 外链静态资源本地化
  - 能自动抓图片、CSS、JS、字体、音视频等静态资源
  - 不能保留运行时联网请求
- 无缩略图课件展示
  - 统一走前端默认占位样式
  - 不再强制生成后端默认缩略图
- 平板适配
  - 系统尽量约束课件符合平板触控
  - 但某些复杂 3D/WebGL 课件仍要单独微调

### 3.3 尚未系统化但值得后续做

- 课件版本管理历史
- 教材目录导入模板下载
- 更细的事件埋点与效果评估模型
- ZIP 课件包标准化上传
- 自动生成缩略图或首屏快照
- 更严格的安全扫描

## 4. 适合这个系统的课件标准

这是最重要的部分。  
如果新维护者只看一段内容，应先看这里。

### 4.1 课件应满足的硬性要求

- 必须适合平板触控操作
- 必须适配横竖屏
- 必须能在校内内网稳定运行
- 必须能够脱离外网工作
- 必须能绑定到明确教材章节
- 必须足够轻量，避免大资源导致平板卡顿

### 4.2 推荐的技术形态

最推荐：

- 单个 `.html` 文件
- 原生 HTML/CSS/JavaScript
- 或已经打包好的静态前端结果

可以接受：

- HTML + 少量静态资源
- 简单 React 思路生成的最终 HTML
- 引用静态 CDN，但上传后由系统自动本地化成功

不推荐：

- 需要 `npm install` 才能运行的源码工程
- 上传后仍依赖外部接口的页面
- 依赖登录鉴权、在线地图、第三方题库、云服务的页面
- 强依赖 WebSocket、fetch、XHR 的在线应用

### 4.3 交互标准

允许：

- 点击
- 轻量拖动
- 滑块调整
- 翻页
- 点击切换

不应作为唯一核心交互：

- 鼠标悬停 `hover`
- 右键
- 滚轮
- 键盘快捷键

说明：

- 课件可以同时支持鼠标和触控
- 但不能“只有鼠标能操作”

### 4.4 平板视觉标准

- 不要依赖超大固定宽高
- 不要使用超小按钮
- 不要把核心信息放在屏幕边缘难以点击的位置
- 不要让主要内容必须缩放后才能看清
- 需要在 10 到 13 英寸平板上可直接使用

### 4.5 性能标准

- 课件总体积越小越好
- 5MB 以上应视为需要优化
- 15MB 以上当前系统会判为不通过
- 大图、长视频、复杂 3D 场景都要谨慎

## 5. AI 生成课件的推荐方法

这个系统非常适合和 AI 配合使用，但前提是提示词要写对。

### 5.1 最重要的要求

必须明确要求 AI：

- 直接输出完整 HTML
- 不要输出构建命令
- 不要依赖 npm、Vite、Webpack
- 不要依赖运行时外网资源
- 必须适配平板触控

### 5.2 如果要用 React

要明确告诉 AI：

- 可以用 React 思路组织页面
- 但最终必须输出“可直接运行的完整 HTML”
- 不能保留 React CDN、构建步骤、运行时接口请求

### 5.3 教师对 AI 的最佳输入结构

建议老师这样描述需求：

1. 学科、年级、章节
2. 这节课要讲什么
3. 学生需要完成什么操作
4. 课件要呈现什么视觉效果
5. 明确写“适配平板触控、离线运行、直接输出完整 HTML”

## 9. 已知约束与注意事项

### 9.1 不要轻易去掉“上传必须绑定章节”

这是后续统计、搜索、效果评估的基础。

### 9.2 不要轻易放开运行时联网请求

本系统是为校内内网和平板场景设计的。  
如果放开运行时联网请求，系统会在以下方面快速失控：

- 可用性
- 安全性
- 性能
- 统计一致性

### 9.3 不要把“展示作者”和“上传归属”混为一谈

- `author` 是展示信息
- `created_by` 是权限边界

### 9.4 不要把老师视角统计写成全站统计

教师只能看到自己课件相关数据。  
之前这里出过口径错误，后续扩展统计接口时要持续保持这个约束。

### 9.5 前端构建包体偏大

当前 `UserManage` 和主入口包体较大，构建时会出现 chunk 警告。  
这不影响运行，但后续值得做按页拆包。

## 10. 建议的后续迭代方向

推荐优先级：

1. 课件版本历史和版本对比
2. 更精细的学习事件埋点

5. 前端按页拆包和首屏性能优化

7. 更严格的课件安全扫描

## 11. 给 AI 工具的直接指令建议

如果让 AI 接着维护这个系统，建议先告诉它：

1. 这是一个面向校内平板和内网环境的教学课件平台
2. 教师上传 HTML 课件，上传时必须绑定教材末级章节
3. 课件必须支持平板触控，不能依赖运行时联网请求
4. `animations.py` 是上传、校验、AI 建议和资源本地化的核心入口
5. `stats.py` 里的教师视角必须限域到教师自己的课件
6. 任何新功能都应优先保证平板可用性和章节数据完整性

可以直接把这段话发给 AI，作为上下文起点。

---

## 12. 最后结论

这个系统的本质不是“网页播放站”，而是“平板教学课件管理与分析系统”。

接手后做任何改动，都建议先问自己三个问题：

1. 这会不会破坏平板触控体验？
2. 这会不会破坏章节绑定和统计口径？
3. 这会不会让课件重新依赖外网？

如果答案里有一个是“会”，就应当重新设计方案。
