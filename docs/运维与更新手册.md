- `/home/binyu/文档/trae_projects/edusimu/frontend`

- [deploy_live_frontend.sh](/home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_frontend.sh)

```bash
bash /home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_frontend.sh
```

这个脚本会固定执行：

1. 在源码目录执行 `npm run build`
2. 把 `frontend/dist` 同步到 `/var/www/edusimu/frontend/dist`
3. 统一修正线上前端目录权限为 `www-data:www-data`
4. 打印线上 `GeoGebraCreator` 和 `index.html` 的最新文件时间

### 6.2 手动做法

```bash
cd /home/binyu/文档/trae_projects/edusimu/frontend
npm run build
sudo mkdir -p /var/www/edusimu/frontend/dist
sudo rsync -a --delete /home/binyu/文档/trae_projects/edusimu/frontend/dist/ /var/www/edusimu/frontend/dist/
sudo chown -R www-data:www-data /var/www/edusimu/frontend
```

说明：

- 当前前端只要替换静态文件，通常不需要重启 `nginx`
- 如果页面仍显示旧内容，优先怀疑浏览器缓存，不是服务没更新

### 6.3 前端更新后如果看不到变化

优先排查：

1. 是否真的覆盖到了 `/var/www/edusimu/frontend/dist`
2. 浏览器是否缓存了旧文件
3. Nginx 配置是否仍然指向 `/var/www/edusimu/frontend/dist`

让用户执行：

- `Ctrl + F5`

如果是图片缓存，必要时要更换图片文件名或修改资源 URL。

这个系统不能只备份数据库。

必须同时备份：

- 数据库快照

- 课件元数据还在

## 10. 常见运维场景

### 10.1 端口被占用

如果本地执行：

```bash
uvicorn app.main:app --reload --port 8000
```

提示：

- `Address already in use`

说明线上 `edusimu-backend` 已经占用了 `8000`。

处理办法：

1. 改用其他端口本地调试
2. 或先停掉线上后端再启动本地

### 10.2 前端改了但页面还是旧的

高概率原因：

- 浏览器缓存
- 实际访问的是旧 `dist`
- 没重启 `nginx`

### 10.3 上传课件后显示异常

先查三类：

1. 后端日志里是否有上传报错
2. 课件是否依赖在线脚本或接口
3. 课件是否本身就不适合平板触控

### 10.4 平板显示黑屏

高概率原因：

- 课件依赖外网脚本，但平板拿不到
- WebGL 课件在平板上性能过低
- 课件布局本身不适合平板

优先处理：

1. 把外链脚本本地化
2. 改沉浸播放布局
3. 对单个课件做平板专用优化

### 10.5 图片或缩略图改了但用户还看到旧图

高概率是图片缓存。

处理方法：

1. 先让用户 `Ctrl + F5`
2. 不行就更换图片文件名
3. 或修改数据库里的缩略图 URL，强制浏览器重新请求

## 15. 单元复习课件的登记、更新与平板排障

本节适用于以下三套静态单元复习课件：

| 课件 | 当前课件 ID | 当前目录节点 ID | 静态直链 |
| --- | ---: | ---: | --- |
| 万有引力与宇宙航行 | 339 | 1174 | `/edusimu/unit-review/gravity-unit/index.html` |
| 机械能与能量守恒 | 340 | 1175 | `/edusimu/unit-review/mechanical-energy-unit/index.html` |
| 动量与动量守恒定律 | 341 | 1176 | `/edusimu/unit-review/momentum-unit/index.html` |

以上 ID 是本次登记后的当前值。后续更新应保持不变；如重新建库或重新登记，应以数据库和导入报告为准。

### 15.1 为什么静态直链能打开，课件目录里却没有

这三套课件存在两个不同的访问入口：

1. `frontend/public/unit-review/` 构建后由 Nginx 提供静态直链。
2. 目录内课件由数据库中的 `Animation` 记录、目录绑定和后端 `/uploads/...` 文件共同提供。

因此，只把 HTML 复制到服务器并发布前端，只能保证直链可访问，**不会自动把课件加入教材目录**。目录中不显示时，应检查是否完成登记，而不是反复重启 Nginx。

专用登记脚本：

- `scripts/import_unit_review_courseware.py`

受限发布入口：

- `scripts/remote_deploy_bundle.sh`

登记脚本会完成：

1. 校验三套 HTML。
2. 找到对应教材分册、章节和“单元复习”目录节点。
3. 通过正常课件上传流程生成 `/uploads/...` 文件。
4. 创建或更新 `Animation` 记录并保持目录绑定。
5. 发布并审核通过课件。
6. 输出 `tmp/unit-review-import-report.json` 报告。

如果存在校验错误、未登记的同名课件、重复来源或目录匹配异常，脚本会停止，不应跳过检查强行写库。

### 15.2 修改已有课件时如何更新目录中的副本

只替换 `frontend/public/unit-review/` 不会自动更新目录正在播放的旧上传包。必须同时执行“登记脚本更新”和“前端静态发布”。

当前登记脚本按源文件与已登记上传包的 SHA-256 判断：

- 内容未变化：写入 `skipped`，不重复上传。
- 内容已变化：生成新上传包，写入 `updated`，保留原课件 ID 和目录绑定。
- 数据库提交成功后才删除旧上传包。
- 执行 `apply` 前自动备份 PostgreSQL，备份位于 `/var/www/edusimu/backups/unit-review-<UTC 时间>/`。

如果执行报错，先保存并检查输出和导入报告。不要在原因不明时连续重复执行，也不要手工覆盖整个 `backend/uploads` 或线上数据库。

### 15.5 学生端无法向下滚动的兼容问题

本次故障的表现为：课件能够打开，但无法向下滚动，下方内容不可见。

根因是课件主容器只有 `height:100dvh`，同时 `html, body` 使用 `overflow:hidden`。旧版 Android WebView 不支持 `dvh` 时会丢弃高度声明，主容器变成内容高度，内部滚动区失去高度约束，外层页面又不能滚动。

修复方式是在三套课件主容器中同时提供旧版回退和现代高度，**顺序不能反过来**：

```css
#app {
  height: 100vh;
  height: 100dvh;
}
```

支持 `dvh` 的浏览器使用第二个声明；不支持的浏览器忽略第二个声明并使用 `100vh`。修改后必须同时更新静态直链和目录内上传包。

机械能课件的全屏规则中另有 `height:100dvh`，基础 `#app` 已有 `100vh` 回退，且全屏规则包含 `position:fixed; inset:0`，无需重复添加同一条回退。

### 15.6 更新后的最小验收

1. 三个静态直链均返回 HTTP 200。
2. 从导入报告的 `updated` 中取得目录内课件 `file_url`，确认其也返回 HTTP 200。
3. 分别计算线上文件 SHA-256，与本地源文件及报告中的 `sha256` 一致。
4. 确认目录中的课件 ID、目录节点和发布状态没有被意外改变。
5. 在 1000×600 视口下逐套打开，确认 `#app` 高度等于视口高度。
6. 动量课件的滚动容器是 `#stage`，另外两套是 `#main`；确认 `scrollHeight > clientHeight`，设置 `scrollTop` 后确实大于 0。
7. 将 `#app` 内联高度设为 `100vh`，模拟旧 WebView 回退，再重复滚动检查。
8. 从网站课件目录实际打开一次，确认播放页也使用新上传包。

快速核对哈希的方法：

```bash
shasum -a 256 frontend/public/unit-review/momentum-unit/index.html
curl -fsS 'http://10.50.159.62:3003/edusimu/unit-review/momentum-unit/index.html' | shasum -a 256
# FILE_URL 使用导入报告 updated 中对应课件的 file_url。
curl -fsS "http://10.50.159.62:3003${FILE_URL}" | shasum -a 256
```

学生端已打开的旧页面不会自动应用修复。更新后应退出课件重新打开；若仍为旧内容，再清理应用缓存或重启应用。不要一看到旧内容就重复导入数据库。
