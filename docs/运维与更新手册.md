## 4. 当前服务关系

- 浏览器访问 Nginx
- Nginx 提供 `/var/www/edusimu/frontend/dist`

### 4.2 后端

- `/uploads`

其中包括：

- 课件 HTML 文件
- 缩略图
- 自动本地化后的外链静态资源

## 5. 日常检查命令

### 5.1 查看服务状态

```bash
sudo systemctl status edusimu-backend --no-pager
sudo systemctl status nginx --no-pager
sudo systemctl status postgresql --no-pager
```

### 5.2 查看后端日志

```bash
sudo journalctl -u edusimu-backend -n 100 --no-pager
```

```bash
sudo journalctl -u edusimu-backend -f
```

### 5.3 查看 Nginx 日志

不同机器路径可能略有不同，常见为：

```bash
sudo tail -n 100 /var/log/nginx/access.log
sudo tail -n 100 /var/log/nginx/error.log
```

## 6. 前端更新流程

前端源码目录：

- `/home/binyu/文档/trae_projects/edusimu/frontend`

推荐脚本：

- [deploy_live_frontend.sh](/home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_frontend.sh)

### 6.1 推荐做法

```bash
bash /home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_frontend.sh
```

这个脚本会固定执行：

1. 在源码目录执行 `npm run build`
2. 把 `frontend/dist` 同步到 `/var/www/edusimu/frontend/dist`
3. 统一修正线上前端目录权限为 `www-data:www-data`
4. 打印线上 `GeoGebraCreator` 和 `index.html` 的最新文件时间

### 6.2 手动做法

```bash
cd /home/binyu/文档/trae_projects/edusimu/frontend
npm run build
sudo mkdir -p /var/www/edusimu/frontend/dist
sudo rsync -a --delete /home/binyu/文档/trae_projects/edusimu/frontend/dist/ /var/www/edusimu/frontend/dist/
sudo chown -R www-data:www-data /var/www/edusimu/frontend
```

说明：

- 当前前端只要替换静态文件，通常不需要重启 `nginx`
- 如果页面仍显示旧内容，优先怀疑浏览器缓存，不是服务没更新

### 6.3 前端更新后如果看不到变化

优先排查：

1. 是否真的覆盖到了 `/var/www/edusimu/frontend/dist`
2. 浏览器是否缓存了旧文件
3. Nginx 配置是否仍然指向 `/var/www/edusimu/frontend/dist`

让用户执行：

- `Ctrl + F5`

如果是图片缓存，必要时要更换图片文件名或修改资源 URL。

## 7. 后端更新流程

后端源码目录：

- `/home/binyu/文档/trae_projects/edusimu/backend`

线上后端目录：

- `/var/www/edusimu/backend`

### 7.1 本地编译检查

```bash
cd /home/binyu/文档/trae_projects/edusimu/backend
./venv/bin/python -m compileall app
```

### 7.2 推荐部署脚本

脚本：

- [deploy_live_backend.sh](/home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_backend.sh)

执行：

```bash
sudo bash /home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_backend.sh
```

### 7.3 这个脚本实际做了什么

1. 备份线上 `app` 目录
2. 用源码目录里的 `backend/app` 覆盖线上后端代码
3. 切换到线上后端虚拟环境
4. 编译检查
5. 执行数据库初始化与补字段逻辑
6. 重启 `edusimu-backend`
7. 校验服务状态

### 7.4 额外说明

这个脚本里包含“物理教材目录”的特殊处理：

- 如果线上物理课件已经绑定了教材目录
- 就会跳过物理目录重建

这是为了避免重新导入目录后把现有课件绑定关系打乱。

## 8. 数据库与文件备份

这个系统不能只备份数据库。

必须同时备份：

- 数据库
- 上传文件目录

### 8.1 需要备份的内容

数据库：

- PostgreSQL 数据

文件：

- `/var/www/edusimu/backend/uploads`

因为课件 HTML、缩略图、外链资源本地化缓存都在这里。

### 8.2 最低建议

每天至少做一次：

- 数据库备份
- `uploads` 目录备份

### 8.3 恢复的最小集合

如果要恢复系统，至少要有：

- 数据库快照
- `uploads/` 文件
- 线上 `.env`

只恢复数据库，不恢复 `uploads/`，会导致：

- 课件元数据还在
- 但实际 HTML 或缩略图丢失

## 10. 常见运维场景

### 10.1 端口被占用

如果本地执行：

```bash
uvicorn app.main:app --reload --port 8000
```

提示：

- `Address already in use`

说明线上 `edusimu-backend` 已经占用了 `8000`。

处理办法：

1. 改用其他端口本地调试
2. 或先停掉线上后端再启动本地

### 10.2 前端改了但页面还是旧的

高概率原因：

- 浏览器缓存
- 实际访问的是旧 `dist`
- 没重启 `nginx`

### 10.3 上传课件后显示异常

先查三类：

1. 后端日志里是否有上传报错
2. 课件是否依赖在线脚本或接口
3. 课件是否本身就不适合平板触控

### 10.4 平板显示黑屏

高概率原因：

- 课件依赖外网脚本，但平板拿不到
- WebGL 课件在平板上性能过低
- 课件布局本身不适合平板

优先处理：

1. 把外链脚本本地化
2. 改沉浸播放布局
3. 对单个课件做平板专用优化

### 10.5 图片或缩略图改了但用户还看到旧图

高概率是图片缓存。

处理方法：

1. 先让用户 `Ctrl + F5`
2. 不行就更换图片文件名
3. 或修改数据库里的缩略图 URL，强制浏览器重新请求

- [control.sh](/home/binyu/文档/trae_projects/edusimu/scripts/control.sh)
- [deploy_live_backend.sh](/home/binyu/文档/trae_projects/edusimu/scripts/deploy_live_backend.sh)

如果看到旧脚本，不要先执行，先读内容，确认它是不是只适用于当时的临时状态。

## 12. 推荐的更新顺序

如果一次改动同时涉及前后端，建议顺序：

1. 在工作区改源码
2. 本地编译或构建检查
3. 部署后端
4. 部署前端
5. 重启服务
6. 检查日志
7. 浏览器实际验证

不要先改线上文件再反推源码，否则很容易产生漂移。

## 13. 上线后的最小验收清单

每次更新后至少检查：

1. 登录是否正常
2. 首页课件列表是否正常加载
3. 教师上传课件是否正常
4. 管理员审核发布是否正常
5. 学生播放课件是否正常
6. 统计页是否正常返回数据
7. `journalctl -u edusimu-backend` 是否有新的异常

## 15. 最后提醒

- 数据库

- 线上代码与配置
